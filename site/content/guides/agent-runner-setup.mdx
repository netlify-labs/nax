# Give Agent Runners tools and skills with netlify-agent-kit

`netlify-agent-kit` gives the agent in a Netlify Agent Runner what it needs:

- tools such as FFmpeg;
- agent skills;
- read-only clones of related repositories;
- a check that required secrets exist.

You configure a repo once. After that, every agent run installs everything before the agent starts. Deploys, CI and local installs are left alone, and nothing it installs ends up in the agent's pull request.

## Why it exists

Agent Runners run in Netlify build containers: Ubuntu, Node, no root and no `apt`. A repo that needs anything beyond that has to install it itself, during environment setup, without root, and without the files landing in the agent's commits. By hand, that takes a setup script, a `postinstall`, environment detection, vendored skills and `AGENTS.md` notes. Detection is the easy part to get wrong: setup has `BUILD_ID` and `DEPLOY_ID` set, so it looks like a deploy build.

## Add it to a repo

```sh
npx netlify-agent-kit add hyperframes
npm install
```

Commit `package.json` and `AGENTS.md`. `add` finds the HyperFrames project and the version it pins, and writes:

```json
{
  "scripts": { "postinstall": "netlify-agent-kit install || exit 0" },
  "devDependencies": { "netlify-agent-kit": "^0.1.0" },
  "netlifyAgent": { "hyperframes": { "version": "0.8.217", "dir": "video" } }
}
```

It also adds a section to `AGENTS.md`, so the agent knows what's installed. An existing `postinstall` is kept, and ours runs after it.

## Commands

| Command | Who runs it | What it does |
| --- | --- | --- |
| `npx netlify-agent-kit add hyperframes` | You, once | Configures the repo. `--version` and `--dir` override what it detects. |
| `netlify-agent-kit install` | Your `postinstall` | Installs everything, in agent runners only. `--dry-run` shows what it would install, `--force` installs anywhere. |
| `npx netlify-agent-kit status` | You or the agent | Shows what the last install did. |

## Configure more

Presets cover the common cases. Everything else goes under the same `netlifyAgent` key, or in `netlify-agent.json`:

```json
{
  "netlifyAgent": {
    "hyperframes": { "version": "0.8.217", "dir": "video" },
    "secrets": ["SENTRY_AUTH_TOKEN"],
    "repositories": [{ "repo": "netlify/design-tokens", "ref": "v3.2.0" }],
    "tools": ["ffmpeg"],
    "skills": [
      { "from": "github:my-org/private-skills#v1.4.0", "path": "skills", "auth": { "env": "SKILLS_TOKEN" } },
      { "from": "./tools/skills/house-style" }
    ],
    "run": ["npx playwright install chromium"]
  }
}
```

| Key | What it does |
| --- | --- |
| `hyperframes` | FFmpeg, the HyperFrames skills shipped in its npm package, and HyperFrames' headless Chrome. |
| `secrets` | Environment variable names to check. Values are never printed. |
| `repositories` | Read-only shallow clones into `~/repos/<owner>/<name>`. |
| `tools` | `ffmpeg`, installed without root and linked into `~/.local/bin`. |
| `skills` | From `npm:<pkg>@<version>`, `github:<owner>/<repo>#<ref>` or a local folder. Copied into `.claude/skills` and `.agents/skills`, never over an existing skill. |
| `run` | Extra commands, after everything else. |
| `mcpServers` | Experimental: adds servers to `~/.claude.json` when `"experimental": { "mcpServers": true }` is set. |
| `strict` | Fail the install when a step fails. Off by default: failures are recorded instead. |

For a private source, `auth` names the environment variable that holds the token. Set the value as a Netlify environment variable on the site.

- **GitHub:** the token travels only in an `Authorization` header. Without `auth`, GitHub sources use `NETLIFY_AGENT_KIT_GITHUB_TOKEN`, `GITHUB_TOKEN` or `GH_TOKEN`, whichever is set first.
- **npm:** the temporary `.npmrc` contains `${VARIABLE_NAME}`, which npm fills in itself, so the token is never written to disk.

## Where it installs

| Environment | `install` |
| --- | --- |
| Agent Runner environment setup (`NETLIFY=true`, `CONTEXT=dev-server`) | Installs |
| The agent's shell (`NETLIFY_AGENT_RUNNER_ID` set) | Installs |
| Netlify deploys, CI, local installs, `netlify dev` | Skips |
| `--force` | Installs |

## Keeping it out of the agent's changes

Installed skills and project tool links are listed in a managed block in `.git/info/exclude`, git's per-clone ignore file. That file isn't committed, so the paths never show up in `git status`. Everything else lives outside the repo: tools in `~/.cache/netlify-agent-kit/`, links in `~/.local/bin`, and clones in `~/repos/`.

The record of the last install, at `~/.cache/netlify-agent-kit/last-install.json`, lists each step, its result and timing, with environment variable names only.

## Use it from code

NAX uses the same detection for `nax ci`:

```js
const { detect, install, status } = require('netlify-agent-kit')
```
